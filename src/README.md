## التكوين

### 1. إعداد Firebase

افتح ملف `/lib/firebase.ts` وأضف بيانات Firebase الخاصة بك:

\`\`\`typescript
const firebaseConfig = {
  apiKey: "YOUR_API_KEY",
  authDomain: "YOUR_AUTH_DOMAIN",
  projectId: "YOUR_PROJECT_ID",
  storageBucket: "YOUR_STORAGE_BUCKET",
  messagingSenderId: "YOUR_MESSAGING_SENDER_ID",
  appId: "YOUR_APP_ID",
  databaseURL: "YOUR_DATABASE_URL" // مهم لـ Realtime Database
};
\`\`\`

### 2. إعداد Firestore Database

قم بإنشاء Collections التالية في Firestore:

#### Collection: `products`
\`\`\`json
{
  "name": "Product Name",
  "type": "firebase" | "domain",
  "description": "Product description",
  "plans": [
    {
      "id": "plan-1",
      "name": "Basic",
      "price": "$99",
      "features": ["Feature 1", "Feature 2"]
    }
  ],
  "createdAt": "timestamp"
}
\`\`\`

#### Collection: `buyers`
\`\`\`json
{
  "name": "Buyer Name",
  "email": "buyer@example.com",
  "products": [
    {
      "productId": "product-id",
      "planId": "plan-id",
      "allowedDomains": 5  // فقط للمنتجات من نوع domain
    }
  ],
  "createdAt": "timestamp"
}
\`\`\`

### 3. إعداد Realtime Database

⚡ **تحديث مهم:** تم تغيير بنية Realtime Database. راجع [`⚡_RTDB_STRUCTURE_UPDATE.md`](./⚡_RTDB_STRUCTURE_UPDATE.md)

**البنية الجديدة:**

\`\`\`json
{
  "licenses": {
    "apps": {
      "PRODUCT_ID": {
        "appIds": ["1:123:android:abc"]
      }
    },
    "domains": {
      "PRODUCT_ID": {
        "domains": ["example.com", "site.com"]
      }
    }
  }
}
\`\`\`

**ملاحظة:** البيانات الآن مُنظمة حسب نوع المنتج وليس حسب UID المستخدم

### 4. قواعد Firebase Security Rules

#### Firestore Rules:
\`\`\`
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Products - read by all authenticated users, write only by admins
    match /products/{productId} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && get(/databases/$(database)/documents/buyers/$(request.auth.uid)).data.isAdmin == true;
    }
    
    // Buyers - read/write by owner or admin
    match /buyers/{buyerId} {
      allow read: if request.auth != null && (request.auth.uid == buyerId || get(/databases/$(database)/documents/buyers/$(request.auth.uid)).data.isAdmin == true);
      allow write: if request.auth != null && get(/databases/$(database)/documents/buyers/$(request.auth.uid)).data.isAdmin == true;
    }
  }
}
\`\`\`

#### Realtime Database Rules:
\`\`\`json
{
  "rules": {
    "licenses": {
      "$uid": {
        ".read": true,
        ".write": "$uid === auth.uid"
      }
    }
  }
}
\`\`\`

### 5. تعيين المدراء

في ملف `/contexts/AuthContext.tsx`، ابحث عن:

\`\`\`typescript
const ADMIN_UIDS = ['ADMIN_UID_HERE'];
\`\`\`

واستبدل `ADMIN_UID_HERE` بـ UID الخاص بحساب المدير في Firebase.

## أنواع المنتجات

### 1. Firebase App (`type: "firebase"`)
- للتطبيقات التي تستخدم Firebase
- الترخيص عبر Firebase App ID
- يمكن للمشتري إضافة معرفات تطبيقات متعددة

### 2. Domain License (`type: "domain"`)
- لقوالب HTML أو Blogger
- الترخيص عبر الدومينات
- يحدد المدير عدد الدومينات المسموح بها لكل مشتري

## سير العمل

### للمستخدم الجديد:
1. يقوم المدير بإضافة بريد المشتري في صفحة "إدارة المشترين"
2. يقوم المشتري بالتسجيل باستخدام نفس البريد المضاف
3. يقوم المدير بتعيين المنتجات للمشتري
4. يمكن للمشتري الآن إدارة تراخيصه

### للمدير:
1. إضافة المنتجات مع خططها المختلفة
2. إضافة المشترين
3. تعيين المنتجات للمشترين مع تحديد الخطة
4. للمنتجات من نوع Domain، تحديد عدد الدومينات المسموح بها

## الصفحات

- **Login/Register**: تسجيل الدخول والتسجيل
- **My Products**: عرض وإدارة المنتجات والتراخيص
- **Account**: إدارة الحساب الشخصي
- **Add Products** (Admin): إضافة منتجات جديدة
- **Edit Products** (Admin): تعديل أو حذف المنتجات
- **Manage Buyers** (Admin): إدارة المشترين وتعيين المنتجات
